Terraform Multi-Cloud VPN Deployment Guide  |  AWS / Azure / GCP  |  v1.0

This guide covers deploying a Site-to-Site IPSec VPN on AWS, Azure, or GCP using Terraform, attaching to an existing VPC/VNet/Network.

Part 2 — Authentication

Option A — Okta SSO / Federated Role (Recommended)

If your organization uses Okta with AWS SSO, set up the profile once:

aws configure sso

Enter when prompted:

SSO session name: okta
SSO start URL:    https://your-org.awsapps.com/start
SSO region:       us-east-1
SSO registration scopes: sso:account:access

Authenticate via Okta in the browser. Then log in before each session:

aws sso login --profile Cloud_DevOps

Verify:

aws sts get-caller-identity --profile Cloud_DevOps

Set in terraform.tfvars:

aws_profile = "Cloud_DevOps"
No credentials stored anywhere — Terraform uses the SSO session token.

Option B — Default Credential Chain

If credentials are already configured via aws configure, leave aws_profile empty:

aws_profile = ""

Option C — Static Credentials

aws_profile    = ""
aws_access_key = "AKIAIOSFODNN7EXAMPLE"
aws_secret_key = "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY"
Not recommended for production. Use Okta SSO or IAM roles instead.

Part 3 — Get the Code

git clone https://github.com/gsbarure/terraform-multicloud-vpn.git
cd terraform-multicloud-vpn

Part 4 — Configure

4Go to the AWS environment folder 
cd envs\aws
5Create your tfvars file 
copy terraform.tfvars.example terraform.tfvars

Edit terraform.tfvars:

project_name = "multicloud-vpn"
environment  = "dev"
region       = "us-east-1"

aws_profile = "Cloud_DevOps"        # Okta SSO profile name

on_prem_gateway_ip = "203.0.113.10"    # Public IP of on-prem device
on_prem_cidr       = "192.168.1.0/24"  # On-prem network CIDR
shared_key         = "MyVPNKey2026abc" # Alphanumeric only

aws_vpc_id = "vpc-xxxxxxxxxxxxxxxxx"
aws_route_table_ids = [
  "rtb-xxxxxxxxxxxxxxxxx",
  "rtb-yyyyyyyyyyyyyyyyy"
]
⚠️ shared_key: Alphanumeric characters only. No @, !, #, - or spaces.
6Find your VPC ID and Route Table IDs 
aws ec2 describe-vpcs --region us-east-1 --output table
aws ec2 describe-route-tables --filters "Name=vpc-id,Values=vpc-XXXXXXXX" --region us-east-1 --output table

Part 5 — Deploy

7Initialize 
terraform init
Expected: Terraform has been successfully initialized!
8Preview 
terraform plan

Review resources. No changes made at this step.

9Deploy 
terraform apply -auto-approve
⏳ Takes 5–10 minutes. AWS VPN connection provisioning takes time — this is expected.

Part 7 — Customer Configuration File

envs/aws/vpn-customer-config.txt is auto-generated after every apply. Send this to your on-premises network team.

It contains:

  • Tunnel 1 and Tunnel 2 outside IP addresses
  • Pre-shared keys for both tunnels
  • IKE phase 1 and phase 2 parameters
  • Inside IP addresses for tunnel interfaces
  • Static routing instructions

Part 8 — Verify in AWS Console

  1. Go to: VPC → Site-to-Site VPN Connections
  2. Find your VPN Connection ID from the output
  3. Status: Available
  4. Tunnel Details tab: tunnels show UP once on-prem device is configured

Part 9 — Cleanup

terraform destroy -auto-approve
Removes VPN Gateway, Customer Gateway, VPN Connection, and route propagation. Does not modify the existing VPC.
